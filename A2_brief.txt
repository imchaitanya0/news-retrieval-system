Part I: Learning from Click-Logs
Team assignment (groups of 2). Due: September 20, 2026.
Building on Assignment 1, you will add behavioural signals from click-logs, implement a reranker, reproduce a baseline then beat it with an ablation, and analyse serving and scale.
Q1. Click-History & Session Features
Engineer behavioural features from the click-logs for both datasets:
1. Click-history features: User’s recent clicked articles (titles, categories, embeddings), click
count, recency-weighted history (exponential decay)
2. Session features: Within-session click patterns, dwell time (if available), position bias
3. Article features: Popularity, freshness (time since publish), category match with user history
4. Behavioural-window boundary: Enforce that no future clicks leak into features at training
or serving time
Q2. Re-Ranker
Implement a two-stage retrieve-then-rank pipeline:
1. Use Assignment 1’s candidate generator to retrieve top-K candidates (K ∼ 100–200)

2. Train a re-ranker over the engineered behavioural features:
• Option A: GBDT (LightGBM/XGBoost) over hand-crafted features
• Option B: A small neural ranker (e.g., NRMS-style [Wu et al., 2019] or a simple MLP)
3. Score and re-rank the candidates
4. Report AUC, MRR, nDCG@5, nDCG@10 before and after re-ranking
Q3. Baseline Reproduced, Then Beaten
1. Reproduce the official/starter baseline (e.g., NRMS from the ebnerd-benchmark repo, or the
MIND baseline) on both datasets
2. Improve with one principled change (e.g., better user encoding, attention over history, categoryaware features, freshness weighting)
3. Ablation: Run an ablation study isolating the contribution of your improvement
4. Statistical significance: Claimed gains must ship a paired bootstrap 95% CI that excludes
zero
Q4. Serving & Scale Analysis
Analyse the serving characteristics of your system:
1. Index memory: Measure the memory footprint of your ANN index and feature store
2. Latency: Measure p99 retrieval latency (candidate generation + re-ranking) for a single user
request
3. Cost/QPS: Back-of-envelope estimate of cost per 1000 queries at a target SLA (e.g., p99 <
100ms)
4. Scaling argument: How would your system scale to 10× the current load? What breaks first?
5. A measured local benchmark plus a scaling argument suffices
Q5. Extended Evaluation
Extend the evaluation harness from Assignment 1:
• Report all metrics (AUC, MRR, nDCG@5, nDCG@10, diversity, novelty, coverage) for the full
two-stage pipeline
• Include at least two slices: cold-start vs. warm, head vs. tail
• Bootstrap 95% CI for all reported metrics
• Submit final predictions to both Codabench leaderboards and include screenshots
